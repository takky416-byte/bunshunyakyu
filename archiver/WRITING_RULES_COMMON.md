# ブログ記事 執筆ルール(共通・全ブログ向け)

文春野球友の会サイト(yakyu.bunshun.jp)へブログ記事を自動投稿するツール
(`post_blog.py`)に読み込ませる原稿を、ChatGPT等に書いてもらうための共通ルールです。

**このファイルの内容を、記事を書いてもらうたびにChatGPTへの指示(プロンプト)の
冒頭にそのまま貼り付けてください。** その後ろに、書いてほしい記事のテーマ・
タイトルの方向性・トーンなど、その記事固有の指示を続けて書けばそのまま使えます
(ブログごとに別ファイルを用意する運用はしていません)。

このルールに沿わない出力は、自動投稿時に書式崩れ・改行の欠落・画像が入らない
などの不具合の原因になります。

**このルールは、コード実行機能(Advanced Data Analysis等)と画像生成機能が
使えるChatGPT(ChatGPT Plus/Team等)を前提にしています。** 本文の作成だけで
なく、挿絵の生成・zipファイルへのまとめまでChatGPTに行わせ、人間は出来上がった
zipをダウンロードして `post_blog.py --batch-zip` に渡すだけで済むようにする
ことが目的です(画像を1枚ずつ手作業でフォルダに置く必要がなくなります)。

## テーマ・題材について

- この指示の後ろに具体的なテーマ(何について書くか)が指定されていない場合は、
  テーマを自分で考えて決めてください。「何について書けばよいですか」のように
  聞き返さず、そのまま記事を書いてください。
- 決めるテーマは、このブログの文脈(この指示と一緒に伝えられているジャンルや
  過去の記事の傾向など)に沿った、1つの記事として成立する程度に具体的な
  ものにしてください(「野球全般について」のような漠然としたテーマにしない)。
- 決めたテーマが伝わるよう、1行目のタイトルにテーマを反映させてください。

## 出力全体の形式

- 1行目に記事タイトルを1行で書く。
- 2行目は空行にする。
- 3行目以降が本文。
- 見出し(下記「見出し」を参照)以外の目的で `#` を段落の先頭に書かない。
  箇条書き記号(`-`・`*`・`1.`)は使わない(このツールでは解釈されず、記号が
  そのまま文字として表示されてしまう)。

## 段落

- 段落と段落の間は、必ず1行の空行で区切る。
- 1つの段落の中で改行したい場合は、そのまま改行してよい(自動的に改行として
  扱われる)。`<br>` と明示的に書く必要はない。

## 文字装飾

太字・斜体・下線には次のHTMLタグを使う。Markdownの `**太字**` / `*斜体*` /
`__下線__` は使わない(特に `__下線__` は下線ではなく太字と解釈されるので注意)。

- 太字: `<b>太字にしたい部分</b>`
- 斜体: `<i>斜体にしたい部分</i>`
- 下線: `<u>下線にしたい部分</u>`
- 組み合わせ可: `<b><u>太字+下線の見出し</u></b>`

## 引用

段落の先頭を `> ` にすると引用(blockquote)になる。複数行にわたる引用は、
継続行の先頭にも `> `(または、行間を1行空けたいだけの場合は単独の `>`)を付ける。

## 見出し

- 段落の先頭を `# `(半角シャープ+半角スペース)にすると、本物の見出し
  (記事本文中の中見出し)になる。例: `# 弘治元年　安芸国・厳島`
- 見出しは前後を必ず空行で区切る(他の段落と同じ)。
- このサイトの本文エディタは見出しのレベルを1つしか持たないため、`##`のように
  `#`を複数書いても同じ見出しになる(章・節のような複数階層の使い分けはできない)。
- 見出しの前後の間隔は、他の段落間と同じ(空行1つ分)。見出しだからといって
  余分に空行を増やす必要はない。
- 見出しには文字装飾(`<b>`/`<i>`/`<u>`)を付けないこと(既にひとつの見出しとして
  強調表示されるため)。
- 見出しを使わない(地の文を`<b><u>見出し</u></b>`のような太字下線の疑似見出しで
  済ませる)ブログの場合は、単にこの記法を使わなければよい。

## 参考文献・出典の書き方

- 記事の末尾に参考文献・出典を載せる場合、1件ごとに空行を空けず、1行に1件、
  改行だけで区切って連続して書く(段落としては1つのまとまりのまま)。
  例:
  ```
  陳寿『三国志』魏書
  裴松之注『三国志』
  渡邉義浩『「三国志」軍師34選』PHP文庫
  ```
  このように書くと、一覧として詰まった見た目で表示される。1件ごとに空行を
  入れると、見出しのように間延びして表示されてしまうので避けること。

## 画像の挿入

- 本文中の画像を入れたい位置に、**画像だけの行**として `![説明](ファイル名)`
  と書く(前後を必ず空行で区切る)。説明文は省略可: `![](img1.jpg)`。
- この`![説明](ファイル名)`で参照した画像は、実写真ではなくあなた(ChatGPT)が
  画像生成機能でその都度イラストとして生成し、同じファイル名で下記のzipに
  含めること(`img1.jpg`と書いたら`img1.jpg`という名前で画像を作る)。
- 本文中に複数枚挿入する場合は `img1.jpg`、`img2.jpg` のように連番にする。
- 記事の一番上に出る「ヘッダー画像(アイキャッチ)」は本文中の画像とは別物で、
  本文には含めない。用意する場合は `header.jpg` という名前で生成し、同じzipに
  含める(不要なら生成しなくてよい)。

## タグについて

- 興味関心タグは、記事の本文には一切書かない。1行に1つずつタグ名を書いた
  `tags.txt` を、必ず下記のzipに含める。
- タグは、サイト側に実際に登録されている固定の候補一覧の中からしか選べない
  (実在しないタグ名を自分で考えて書いても使われない)。この会話の中で
  この記事シリーズ(ブログ)の「タグの候補一覧」をまだ教えられていない場合は、
  記事を書く前に、候補一覧を教えてほしいとこちらに確認すること(候補が
  分からないまま `tags.txt` を書かない)。一度教えてもらった候補一覧は、
  以後の記事では覚えておき、毎回聞き直さない。
- 候補一覧を把握したら、その中から記事の内容に合うものを1〜3個自分で選び、
  `tags.txt` に書く(どれを選ぶか、いちいちこちらに確認する必要はない。
  選んだタグと理由は、記事と一緒に一言添えてくれると確認しやすい)。
- 「タグを付けない」と指示された記事は、`tags.txt` を空のまま(中身なし)で
  zipに含める。

## 出力ファイル(zip)について

- 本文は完成したら、コード実行機能を使って以下のファイルを**1つのフォルダに
  まとめず、zipの一番上の階層に直接**入れて1つのzipファイルにまとめ、
  ダウンロードできる形で出力すること(サブフォルダに入れない)。
  - `article.txt` — 1行目がタイトル、2行目が空行、3行目以降が本文(このルール
    に従って書いたもの)
  - 本文中で `![](ファイル名)` として参照した画像ファイル(生成したイラスト)
  - `header.jpg` などのヘッダー画像(生成した場合のみ)
  - `tags.txt`(上記「タグについて」の通り。候補が無ければ空ファイル)
- コード実行機能が使えない場合は、zipにまとめず、本文のテキストと生成した
  画像を個別にそのまま出力すること。

## 出力形式のチェックリスト(ChatGPTへの指示の最後に付けると効果的)

- [ ] 1行目はタイトルのみ、2行目は空行になっているか
- [ ] 箇条書き記号(`-`/`1.`)を使っていないか
- [ ] 見出し以外の場所で行頭に `#` を書いていないか
- [ ] 太字/斜体/下線は `<b>`/`<i>`/`<u>` タグを使っているか(`**`/`__`不使用)
- [ ] 段落と段落の間に空行が1つ入っているか
- [ ] 画像は `![説明](ファイル名)` の形式で、前後が空行になっているか
- [ ] 本文で参照した画像をすべて生成し、同じファイル名でzipに含めたか
- [ ] 本文中にタグの記載がないか(タグは`tags.txt`に書いたか)
- [ ] `article.txt`・画像・`tags.txt` をサブフォルダに入れず、zipの一番上の
      階層に直接入れたか
